# Playbook: autopilot

A queue of PRs handed to one coordinator (the main agent) and carried to verified or through merge. The coordinator owns the verdicts, never the PRs. A multi-day program of many units runs [orchestrate.md](orchestrate.md); one in-session wave runs [fanout.md](fanout.md). The brief template, retry by cause, and the PR-owner force-push and respawn lease rules live in [work-fanout.md](../../stages/work/references/work-fanout.md); follow them there.

Declare the mode before spawning. The grant covers only the PRs the owner named; a PR outside the queue, or one the owner keeps, stops at verified, and a request to state the plan is not a go. The queue request is the go for each PR owner to push its own branch and open its PR.

- `stack` (default): stop when each PR is verified and green at its current head, then hand the queue to the owner; after the handoff no agent pushes without the owner's go. Nothing merges.
- `full`, only on the owner's explicit request: the coordinator lands each verified PR through [ship.md § Land](ship.md#land); a PR that Land leaves `merge-ready` (no `Auto-merge: low-risk` opt-in on the base) or at needs-review goes to the owner.

Rules for the whole run:

- **One PR owner per PR:** a `lead` or `worker` in its own worktree is the only writer of its branch; it never merges, in either mode.
- **Override labels are the owner's:** no agent applies `owner-reviewed` or `allow-test-weakening`. A change that loosens a gate (a raised budget, an allowlist entry) needs a verifier's proof and the coordinator's countersign in the Log; a disabled or soft-failed check comes out.
- **A verdict covers one patch at one head SHA:** this is the verifier's `check full` verdict, not Land's head-bound `## Risk` verdict. After a rebase, the verdict holds only when `git patch-id` is the same at the verdict SHA and the new head and the base brought no change to a file the patch touches or calls into; otherwise a new verdict. Green CI covers only its own head and never stands in for a verdict.
- **Off the base, not stacked:** each PR branches from the base and lands on its own. Stack only when a PR builds on another ([ship.md § Stacked or not](ship.md#stacked-or-not)): it rebases onto its parent's branch, the stack root onto the base, and a restack keeps only the verdicts the rule above lets hold.
- **State:** the plan `## Log` and live `gh` only; every spawn, reported head, verdict with its SHA, retry, `done` and `blocked` is a Log entry.
- **Stop:** on the owner's stop, every agent gets a zero-writes order, reports where it stands, and keeps its brief; log `decision: hold` in the plan `## Log`. Nothing resumes until the owner releases the hold.

1. `brainstorm` — frame the queue in the plan: each PR's goal and done evidence, the mode, the PRs the owner keeps, and which PR builds on which.
2. `work full` — spawn one PR owner per PR per work-fanout.md, with an explicit model, the mode, and the PR-owner exception under FORBIDDEN. The PR owner opens its PR early via `git`, finishes the code, rebases onto the current base, runs the touched paths' checks on the committed head, and reports the code-ready head; it reports every later head. It fixes CI and review threads in [babysit.md](babysit.md)'s order and triage, but rebases and force-pushes only under the PR-owner exception.
3. `check full` — verify once in full at the code-ready head: a `verifier` on a different model family (or the same family when the session's `advisorModel` is `fable`) re-runs the gates, exercises the changed behavior on the real surface, and reads the diff, not the report. Every later head with a new patch-id gets a single verifier, which re-runs the gates at the new head and reads the diff since the verdict SHA; a new full verification only for new behavior, a redesign or a large new diff. Block only on what you can show: a failing run at the head, a failed gate, a bug a user would hit, or a doc line the PR made wrong; a problem the base already has goes to a follow-up.
4. `work full` — fix rounds: each blocking finding goes to its PR owner. Fixes stay on the current base unless the base conflicts, breaks CI, or lands a change to the same files, because each rebase restarts CI. Retry a failed PR owner by cause.
5. `work full` — on the owner's go, arm `/loop 1h` until no delegated work is left. Each tick re-reads this file and the mode, reads `gh pr view`, `gh pr checks` and the Log, and judges each agent by side effects (pushes, PR activity, Log entries), never its status text. An agent that errors, cannot start turns, or shows nothing new past its expected runtime is replaced at once from its logged branch and SHA, and the replacement counts as a retry by cause per work-fanout.md, then `blocked`; one waiting on the owner is not stuck.
6. `git` — `stack`: stop at verified and hand off. `full`: before Land, fetch the base; when its changes can affect the patch (a conflict, a file both sides changed, a change to which checks run), the PR owner rebases, reports the head, and the patch-id rule decides the verdict. Then land bottom-up via [ship.md § Land](ship.md#land). Count rebases from this step's first fetch: a third rebase before the PR lands → park that PR and report to the owner.
7. `handoff` — keep Current State and the `## Log` current; agents end with the session, and next session `session-pickup` respawns PR owners from the Log.

Reply: the mode; each PR with its link, live `gh` state, and verdict SHA; in `full`, Land's `## Risk` verdict and whether it merged, sits `merge-ready`, or needs review; agents replaced, countersigns, parked follow-ups, and decisions waiting on the owner.
